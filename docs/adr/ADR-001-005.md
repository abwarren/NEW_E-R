# ADR-001 — Single FastAPI service on one port

**Status:** accepted · **Date:** 2026-08-30

## Context
Legacy E&R ran 3 processes (Express :4000 → Flask :1080 → Engine :5002) with 2
HTTP hops and hardcoded IPs. The directive demands one service, one API, one
state system, one dashboard, no unnecessary HTTP chain.

## Decision
One FastAPI app serving REST + SSE + static dashboard + in-process eval7 on one
port. No Express, no Flask, no engine container. Equity runs in-process.

## Consequences
- Port chosen: **8090** on this box (:8000 = ConceptPokerMTTpro, :8080 = another
  ConceptPokerMTTpro listener). Configurable via `ER_PORT`.
- The Chrome extension talks directly to the API (CORS + X-API-Key).
- Restart recovery is trivial: state lives in the DB, dashboard reconnects via SSE.

# ADR-002 — State store: SQLite default, PostgreSQL-ready

**Status:** accepted (with a provisioning caveat) · **Date:** 2026-08-30

## Context
The directive: PostgreSQL-backed state, no JSON files as the authoritative
store. On this box, provisioning a PG role/database requires the postgres
superuser (sudo), which the user has not granted during this build.

## Decision
SQLAlchemy state layer with `ER_DB_URL`. Default: SQLite file (`data/er_state.db`,
WAL mode — a real DB, not JSON). PostgreSQL URL (psycopg2) supported by the same
code; migration = create the `new_er` database + role, set `ER_DB_URL`, restart.
Schema DDL is identical across both (SQLAlchemy `create_all` + Alembic-ready).

## Consequences
- All acceptance criteria (persistence, isolation, recovery) are demonstrable now.
- PG switch is one env change once the user provisions the role.
- **BLOCKER NOTE:** PG provisioning requires user action (postgres role/password).

# ADR-003 — Command queue state machine + idempotency

**Status:** accepted · **Date:** 2026-08-30

## Context
Legacy failure: a lost ACK caused duplicate actions. Remote poker control must
be exactly-once from the operator's perspective.

## Decision
Commands live in the DB with an explicit lifecycle
(CREATED→QUEUED→DELIVERED→EXECUTING→ACKNOWLEDGED / TIMEOUT→FAILED).
- Claim is exclusive per (player_id, browser_instance_id).
- ACK is idempotent by command_id.
- The browser extension memoizes executed command_ids and refuses repeats.
- Stale EXECUTING commands time out after `ER_COMMAND_TIMEOUT_SECONDS` (20s).

## Consequences
A command can never execute on the wrong table/bot (identity partition) or
twice (idempotency + memo).

# ADR-004 — Identity: player → browser → table → hand → snapshot

**Status:** accepted · **Date:** 2026-08-30

## Context
Legacy indexed `_tables` by `table_id` alone → multi-bot collisions. The
directive makes player_id first-class.

## Decision
State is partitioned by
`player_id + browser_instance_id + table_id + hand_id + snapshot_version`
(`StateKey`). Every table row, command, event and equity result carries the
scope. Browser instances are bound to exactly one player at first contact
(auto-enroll); the binding is enforced thereafter (cross-player → 403).
Players DB = SQLite (metadata) + OS keyring (passwords) — credentials never in
state DB, logs, API or dashboard.

## Consequences
Two players on the same table, or one player on two tables, can never corrupt
each other's state. Proven by `test_two_players_isolated_state_keys`,
`test_two_bots_same_table_isolated`, `test_two_tables_isolated`.

# ADR-005 — Stale snapshots: visible rejection, no deadlock

**Status:** accepted · **Date:** 2026-08-30

## Context
Legacy: 409 `stale_snapshot` became a permanent rejection (epoch deadlock) and
`_lastSendTime` silently dropped snapshots.

## Decision
- Monotonic `snapshot_version` per scope. Older version → HTTP 409 with the
  current version in the reason (visible, actionable).
- The extension, on 409, resyncs its sequence to the server version and
  continues — recovery is automatic, not blocked.
- Read-time staleness flag (`is_stale`, >30s) shown in the dashboard.
- Hand transitions reset board/hole cards at PRE_FLOP (no phantom cards).

## Consequences
No silent loss, no permanent rejection, no flicker between old/new states.
